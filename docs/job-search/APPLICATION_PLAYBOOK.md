# US-Remote AI/Software Application Playbook

## Target

- Geography: US-remote roles only.
- Compensation filter: prefer roles whose posted base salary floor is >= $260,000/year.
- Role families: AI systems, agentic automation, control planes, AI platform, staff/principal/founding software engineering, technical AI leadership.
- Evidence rule: only claim skills, experience, systems, outcomes, or credentials that can be supported by the candidate resume or public GitHub work.

## Application positioning

Primary positioning:

AI Systems Engineer | Control Planes | Agentic Workflows | Technical Operations

Core story:

Build governed agentic systems that make authority, provenance, approval, validation, and failure handling explicit rather than allowing uncertain model output to silently become production action.

## Guardrails

- Never state that an application was submitted unless a real submission occurred.
- Never fabricate production transactions, customer counts, revenue, testimonials, or employer credentials.
- Never claim Rust, Go, C++, formal methods, OPA/Rego/Cedar/Zanzibar, consensus, exactly-once delivery, or regulated-domain experience unless independently documented.
- For roles requiring US work authorization or US residency, surface the eligibility requirement rather than hiding it.
- Record application URL, date checked, compensation evidence, remote eligibility evidence, tailoring version, and actual submission state.

## Example evidence statement

In my MBM control-plane work, I treated autonomous execution as a gated system rather than allowing discovery logic to write directly into production. I introduced explicit opportunity states, mandatory provenance, human approval, prompt-injection defenses, isolation, and a single-writer boundary for sensitive revenue operations. The goal was to make an agent's authority explicit and auditable, and to ensure that uncertain or unverified intelligence could not silently become a production action.
