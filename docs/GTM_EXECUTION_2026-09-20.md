## Buyer-proof rule

A demand signal is not a buyer.

The state machine is:

DEMAND_SIGNAL -> ACCOUNT_CONTEXT -> CONTACT_VERIFIED -> OUTREACH -> REPLY -> CONVERSATION -> PAID_PILOT -> DELIVERY -> PROOF -> RECURRING

Do not collapse these states.

## Outreach batch rules

- Small, human-review batches.
- Only use verified professional contact details.
- One workflow-specific problem per message.
- One CTA per message.
- No unsupported ROI claims.
- No invented case studies, testimonials or customer names.
- Exclude catch-all addresses from direct send unless separately verified.
- Do not use Contec company email for MBM outreach.

## Sales asset standard

Every campaign batch should have exactly one useful proof-oriented asset:
- workflow before/after map
- 1-page pilot scope
- small calculator/checklist
- screen/demo walkthrough
- quantified process baseline template

Asset status must be one of:
DRAFT -> READY -> PUBLISHED (provider receipt required)

## Pipeline event model

VIEW -> CLICK -> LEAD -> CONVERSATION -> CHECKOUT -> PAYMENT -> DELIVERY -> REVIEW -> UPSELL

Only attributable events may be recorded.

## Engineering gate

No new feature work is justified solely by:
- low outbound volume
- lack of replies before a meaningful test
- desire for more automation
- desire for more connectors
- desire for prettier demos

Engineering becomes eligible when:
- a paid pilot exposes a repeatable blocker, or
- multiple qualified conversations identify the same missing capability.
