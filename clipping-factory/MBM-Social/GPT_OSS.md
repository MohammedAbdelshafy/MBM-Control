# GPT-OSS local provider\n\nMBM-Social can route reasoning-heavy tasks through an OpenAI-compatible local GPT-OSS endpoint.\n\nOpenAI's gpt-oss repository publishes gpt-oss-20b for lower-latency/local use and gpt-oss-120b for higher-reasoning workloads. The models use the Harmony response format and support agentic tool patterns such as function calling, browsing, Python, and structured outputs.\n\n## Configuration\n\nSet GPT_OSS_BASE_URL to the local server base, for example http://localhost:11434 for an Ollama-compatible deployment or another local OpenAI-compatible endpoint.\nSet GPT_OSS_MODEL to the served model name. Default: gpt-oss:20b.\nSet GPT_OSS_API_KEY only when the local OpenAI-compatible gateway requires authentication.\n\nThe registry calls POST {GPT_OSS_BASE_URL}/v1/chat/completions. No public OpenAI API call is made by this adapter.\n\n## Ollama\n\n```bash\nollama pull gpt-oss:20b\nollama run gpt-oss:20b\n```\n\nThen set GPT_OSS_BASE_URL=http://localhost:11434.\n\n## vLLM\n\nOpenAI's reference repository documents serving gpt-oss with vLLM. For example:\n\n```bash\nvllm serve openai/gpt-oss-20b\n```\n\nPoint GPT_OSS_BASE_URL at the resulting local gateway.\n\n## Safety boundary\n\nGPT-OSS is an inference provider. It does not directly mutate the MBM dialer database, publishing queues, or revenue state. Existing quality gates, publishing controls, opportunity airlocks, and single-writer boundaries remain authoritative.\n\n## Rollback\n\nUnset GPT_OSS_BASE_URL. The registry returns to the existing Ollama model selection path.
